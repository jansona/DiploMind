# 上下文取舍：真实 API 对照结果

2026-09-30，使用同一阿里云 `deepseek-v4.1-flash`、非思考模式、temperature
0.2，执行五个合成情景、两种上下文版本、态度/谈判/下令三个阶段，各重复两次。
顺序固定随机交错，60 次请求全部完成，无重试，耗时 216.8 秒。

## 实际服务方计数

| 指标 | 旧版上下文 | 优化上下文 |
|---|---:|---:|
| 请求数 | 30 | 30 |
| 输入 token | 377,913 | 146,507 |
| 输出 token | 3,227 | 3,532 |
| 缓存命中的输入 token | 253,696 | 49,152 |
| 请求耗时中位数 | 3.857 秒 | 3.054 秒 |
| 请求耗时 p95 | 5.528 秒 | 4.647 秒 |

这组拥挤历史合成情景的输入减少 61.2%。两版本总用量为 531,179 token，
不是费用报价。缓存命中率不同，只有每情景两次样本，且模型输出长度不同，
不能把全部延迟差异归因于压缩，也不能推广成所有真实对局都会同幅提速。
请求串行执行，排队时间为零；耗时包含网络与服务端推理。

## 质量并非只有“JSON 合法”

- 早先被闲聊淹没的 BUR 非军事区承诺：旧版两次都声称没有确认承诺；优化版
  两次都识别双方承诺，并在私聊里重新确认
- 明确同意的 TRI 转让：优化版两次都认出已同意的转让并保持对盟友的信任；
  旧版只看见转让事实，因缺失同意上下文而降低信任
- GAL 的虚假占领指控：两版都能引用公开相撞结果，不把指控当作真实占位
- 所有请求均未包含无权查看的私聊测试标记；全部响应通过格式验证

但还有一个关键失败：优化版两次都在决策说明里表示要避开 BUR、选择 GAS，
最终可执行数组却仍写了 `A PAR - BUR`。因此，恢复承诺记忆不等于命令已经
遵守了决策。这是输出前后矛盾，不宜包装成“有策略地背叛”。

## 后续修复与验证边界

新增格式把简短决策说明放在前面，逐单位结构化计划居中，最终 orders 放在
最后；使用同一合法表检查结构化计划和最终命令是否一致。只对冲突单位明确
回退，不用自然语言关键词偷偷改令，也不禁止有意识的背叛或有意自撞。

正在用另一个独立、限额的下令测试比较修复效果、两种性格和思考模式的
速度/质量取舍。该测试结果必须单独记录，不能倒填进本轮 60 次对照。
